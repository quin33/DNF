# 深渊酒馆 S1 · 独立复刻网页

## 管理后台

后台只在设置 `ADMIN_PASSWORD` 后启用。PowerShell 启动示例：

```powershell
$env:ADMIN_PASSWORD = '请使用高强度独立密码'
node server.js
```

访问 `http://localhost:8787/admin` 登录。后台会话有效期为 2 小时，可检索玩家并编辑角色数据；不支持删除、账号密码、玩家会话或探险日志编辑。每次角色保存都会记录审计日志。进行后台操作前请备份 `tavern.db`。

> 从 https://stock.xxapi.icu 的「深渊酒馆」版块完整复刻 UI 布局与全部模块，生成的可独立运行的网页。
> 用于在此基础之上重新制作你自己的游戏。

## 文件结构

```
xiuxian/
├── index.html      # 主页面（全部模块 + 交互逻辑，纯原生 JS，无任何依赖）
├── style.css       # 主题样式（复刻原站暗色幻想风格）
├── data.js         # ★ 游戏世界数据（初始为空：无修士、无座位、无日志——从创建角色开始）
├── server.js       # ★ AI 探险日志服务（Node.js 零依赖，托管页面 + 调用 LLM 生成日志）
├── ai.config.json  # 兼容占位配置（不存放密钥；生产使用环境变量）
├── 启动游戏.bat    # Windows 一键启动（双击即可）
├── 启动控制台.bat  # Windows 本机服务控制台（8790 端口）
├── xiuxian/        # 世界观设定、完整提示词、AI 生成示例日志
└── reference/      # 原站真实截图（抓取自 stock.xxapi.icu，供对照参考）
```

**两种使用方式**：
- **离线体验**：直接用浏览器打开 `index.html`（本地叙事引擎生成日志，无需联网）
- **在线版（推荐）**：`node server.js` 后访问 `http://localhost:8787` —— **首页即原本界面**，首次进入弹登录/注册；登录后角色存在服务器（SQLite），「我的」「冒险者」显示在线角色；**小队页点「单人匹配」→ 服务端匹配真人（2 分钟未满 AI 道友补位）→ 服务端权威 AI 自动生成副本剧情，玩家纯观看实时播放直到结算**（经验/灵石/战利品写回角色）。AI 仅对已登录用户开放，并受请求体、IP 频率和并发限制。
- **本机控制台**：双击 `启动控制台.bat`，访问 `http://127.0.0.1:8790`。控制台可启动、停止、重启网页服务器，切换远程 AI 运行开关，重载配置、检查连接并查看脱敏日志。首次使用请在 `.env` 设置 `CONTROL_PANEL_PASSWORD`；控制台只监听本机回环地址。

## 在线化实现（已整合进 index.html）

- 首次访问弹登录/注册（scrypt 哈希 + 会话 token，`api/auth/*`）
- 角色创建走服务端（`/api/character/create`），「我的」「冒险者」都显示服务端角色
- 「单人匹配」→ WS `/ws` 进入服务端匹配队列 → 攒真人/补 AI 至 4 人 → 自动开本；**匹配界面以圆角标签显示每位参与者的完整角色名 + 修为境界**（空位显示 ?）
- 副本由 `server.js` 权威推进（复用 `game-engine.js`），每步 AI 生成剧情 WS 广播，前端 `online.js` 纯观看
- 结算把经验/灵石/战利品写回 SQLite（`settleRoom`），刷新后角色成长持久
- 单机本地引擎（localStorage/本地推进）保留但在线模式不再使用；`online.html` 旧独立方案已弃用，`/online` 重定向到首页
- `DEPLOY.md`：局域网联机与公网 HTTPS 反代指南

## 接入 AI 探险日志（三步）

1. **启动服务**：双击 `启动游戏.bat`（或 `node server.js`），访问 `http://localhost:8787`
2. **配置 AI（环境变量）**：不要把 API Key 写入 `ai.config.json` 或任何前端文件。启动前设置：
   ```powershell
   $env:AI_BASE_URL = 'https://api.deepseek.com/v1'
   $env:AI_API_KEY = '请填入新生成的 API Key'
   $env:AI_MODEL = 'deepseek-chat'
   $env:AI_MAX_TOKENS = '5000'
   $env:AI_TEMPERATURE = '0.85'
   node server.js
   ```
   也可使用任意 OpenAI 兼容接口。若旧版本曾把 Key 提交到仓库或发送到公网，请立即在提供商后台撤销并重新生成。

   Windows 用户可将 `.env.example` 复制为 `.env`，只填写一次真实配置；之后直接双击启动脚本即可自动加载。直接运行 `node server.js` 时请先在当前终端设置环境变量。`.env` 已被忽略，不会由静态服务提供。
3. **自动切换**：每步探险前端会调用 `/api/ai/story`（完整提示词见 `xiuxian/ai_log_prompt.md`，含世界观/混合叙事/装备类型/技能/背景设定等全部规则）；**AI 调用失败自动重试 1 次，仍失败则回退本地叙事引擎**，游戏永不中断

> 提示：服务启动后，浏览器地址栏输入 `http://localhost:8787/api/health` 可查看 AI 配置状态（configured: true/false）。AI 端点必须先登录账号；生产环境还必须设置高强度、独立的 `ADMIN_PASSWORD`。

## 创建角色流程

游戏从空世界开始，玩家在「👤 我的」标签页创建自己的第一个角色：

1. 输入**角色名**（1~20 字）
2. 选择**灵根**（金/木/水/火/土）——仅作为角色特质展示，不影响属性
3. 选择**性格**（影响组队行为与 AI 叙事风格）
4. 从 **10 种初始装备/道具中选 2 件**（铁剑、聚气丹、火球符、避瘴珠、传音符等，只有故事描述，无属性加成）
5. 初始四维（体魄/身法/神识/气运）由系统在 **1~20 间随机决定**

创建后自动生成修士卡片：修为=练气一层、灵根显示为特质徽章。角色保存在浏览器 `localStorage`（key: `xiuxian_role`），刷新不丢失；「重新创建角色」按钮可重置。

## 储物袋与随身法宝

- **随身法宝**：最多 **5 件**（点击冒险者卡片进入详情，点已装备物品可取下）
- **道具储物袋**：**100 格**（点击储物袋物品可装入随身法宝；同名称道具自动堆叠，如聚气丹×3）
- 初始选择的两件装备/道具存入储物袋，由玩家决定何时随身携带
- 数据存于角色对象：`equipment[]`（随身法宝）与 `bag[]`（储物袋），随角色一起持久化

## 功法 / 术法系统

- 每人可携带 **最多 5 种** 功法或术法（`skills[]`，5 格技能栏 = 装备栏）
- **功法库（`skillPool[]`）**：已学但未装备的功法存于功法库，不参与探险；可在冒险者详情 → 档案页随时 **装备 / 卸下**（装备入栏、卸下回库，永久保留）
- **创建角色时按灵根自动发放**：1 种对应灵根属性的基础**功法** + 1 种基础**术法**
  - 金灵根：庚金炼体诀（功法）+ 金刃术（术法）
  - 木灵根：青木养气诀 + 缠藤术 · 水灵根：玄水凝元功 + 水箭术
  - 火灵根：赤炎心法 + 火球术 · 土灵根：厚土镇岳诀 + 土盾术
- **标签区分**：功法=蓝色标签、术法=紫色标签、灵根属性=青色（卡片徽章 / 详情弹窗 / 创建预览均带标签）
- **功法/术法阶位（稀有度）**：所有功法术法（不论境界）均带 **黄阶 < 玄阶 < 地阶 < 天阶** 四档阶位——初始灵根技能、藏经阁典籍、探险卷轴各有分布；阶位按色区分（黄阶灰 / 玄阶绿 / 地阶紫 / 天阶橙），显示于创建预览、冒险者卡片徽章、档案页技能列表与功法库、藏经阁商品行；AI 叙事提示词含阶位标注；旧存档技能默认黄阶
- 副本叙事会随机融入角色**已装备**的功法/术法（"掐诀施法，火球术应手而出"）；功法库技能不会出现在叙事中
- **探险容错（断线不丢）**：进行中副本**每步落盘持久化**（`xiuxian_runs`），页面关闭/刷新/崩溃后重开**自动恢复并继续推进**（角色引用重新绑定，进度不丢）；页面关闭时 AI 请求中止不计为失败（不写失败日志、不销毁副本）；中断超过 6 小时的副本转为「失败」日志保留记录；结算完成才移除副本并清理快照；无副本但角色卡在「探险中」时自动复位为休息并退还精力
- 创建表单有"将获得"预览，切换灵根实时更新

## 装备独立使用机制

- **每件装备都是独立对象**（`{name, kind, desc, qty, rarity}`），叙事中**分别读取描述**，不再整串堆叠列出
- **按类型准确发挥**（kind 区分动作）：
  - **防具**（道袍/甲/仙衣）→ **披着/披紧**，作用为"护住周身"
  - **武器**（剑/刀/弓）→ **握紧/祭出**，作用为"锋芒毕露"
  - **丹药**（聚气丹等）→ **吞服**，作用为"药力流转"
  - **符箓**（火球符等）→ **激发**，作用为"灵光乍现"
  - **工具**（罗盘/灵锄/避瘴珠）→ **催动/握着**，作用为"灵机自转"
- **判定使用**：每步在合适时机（探索/战斗/首领/搜刮）随机挑选与该场景相关的 1 件装备做 **D20 判定**（`D20 + 场景匹配加成 ≥ 12` 成功）：
  - 成功：该装备按类型发挥效果并写入剧情（"披紧粗布道袍——粗布缝制的道袍……护住周身"）
  - 失败：叙事如实反映（"催动灵锄，可惜时机不对，未能派上用场"）
- 详情页每步显示装备判定徽章（🎒 装备名 · 判定成功/未奏效）
- 装备场景匹配沿用描述关键词映射（避瘴珠→探索、火球符→战斗、兽皮囊→搜刮…）

## 组队副本系统

**匹配与开本**
- 「小队」页点击「⚔️ 单人匹配」进入队列，系统模拟道友加入，凑齐 **4~6 人** 自动开本
- 服务器最多同时进行 **10 个副本**（`MAX_CONCURRENT_DUNGEONS`），满时自动等待
- 开本消耗 10 精力（不足 10 拦截），精力与气血均按现实时间每分钟回复 1 点（封顶上限、离线累计、满值计时归零）；**探险中气血不回复**（战斗中无法恢复，计时在进入/结算/取消时重置），结算战损与角色实际气血一致

**AI 副本剧情**
- 7 座灵墟**全部炼气期可入**；每副本 **6 种敌人**（贴合副本设定的丰富敌人池）+ **2 个首领**（普通首领筑基初期、隐藏首领筑基中期）
- **每局敌人随机 0~3 种**（开本时从敌人池抽取，各自修为在**练气一~十层**随机分布；敌人为 0 种时**跳过战斗阶段**）
- **首领遭遇**：普通副本 **10% 概率**遇到首领（1 段起）；隐藏副本**必定**遭遇（保底 2 段：普通首领 + 隐藏首领）；没遇到首领则跳过首领阶段
- **特殊事件（10% 独立概率）**：触发后副本**难度与奖励整体上调**——敌人数量保底 1~3 种且修为 +2~4 层、检定成功门槛 12→14、**必定遇到首领**、经验 +50%、灵石报酬 +50%、战利品上限 8→12 且品质上调（含传说级）、AI 剧情烘托异象氛围；进行中日志带「✨ 特殊事件」标记
- 阶段流：入谷→探索→（战斗）→（首领）→搜刮→归途，**整局 10~40 段**、**每段 ≤250 字且不设最低字数**（长短随叙事节奏自然起伏，允许短促有力的转折句），允许一行一段
- **副本背景设定**：7 座灵墟各有专属 lore（来历/成因/禁忌），显示在日志详情页顶部
- 战利品结合副本背景：普通搜刮为该副本特色物，首领战利品为该首领专属遗物（如枯骨林白骨将军的「将军虎符」、落仙台仙人残念的「道则碎片」）
- **混合叙事**：**个人高光段**（约三成步骤，不写队友出场，聚焦该角色独当一面的抉择与表现）与**多人配合段**（2~6 名角色协同出演）自然交错
- **战利品全程分配**：战斗缴获/探索发现/搜刮拾取按剧情合理分布，不集中堆在某阶段；**最后一步（归途）AI 会自然交代此行所得战利品的分配与归属**
- **战利品类型不限**：武器/防具/丹药/符箓/材料/杂物/功法术法卷轴等皆可，只要与副本故事设定自洽；每局结算有 **10% 概率额外获得稀有功法/术法卷轴**（AI 起名并写描述，如「《青木养气诀》残卷」）
- **战利品按功劳分配**：每件道具按成员贡献权重（出场/检定/大成功/战损）分配给每位成员，**结算界面显示每个人的收获**（🎒 收获：…），玩家份额入储物袋——为多人游戏（全员真实玩家）设计的分配框架
- **炼器坊**（建筑页点击 🔥 炼器坊，仿铁匠铺布局）：投入两件材料（随身法宝/储物袋），**AI 器道宗师判断组合合理性**（符合修仙世界观，如"铁剑+灵骨碎片"→骨纹灵铁剑；"聚气丹+罗盘"→判为不合理并说明理由），合理则消耗材料产出新法器，不合理则失败（材料五成概率保留/损毁、退一半灵石）；消耗 100 灵石 + 20 精力，CD 2 小时；材料列表与功法库同款排版，默认显示前 5 件、右侧「展开全部 / 收起」；材料区带储物袋同款**稀有度筛选与排序**，并支持按名称/描述/种类/来源**文字搜索**；材料显示**品质标签与稀有度颜色**（普通灰/稀有蓝/珍贵紫/传说橙，卡片边框随品质着色），AI 提示词含品质以决定法器珍奇程度
- **太虚幻境**：玩家主动选择功法或术法并填写 100 字以内的期望目标，AI 结合角色境界、灵根、特质、功法栏与功法库生成符合世界观的新能力，效果强度自行对应黄阶、玄阶、地阶或天阶；当前免费且无冷却，费用与冷却接口已预留
- **藏经阁**（建筑页点击 📖 藏经阁，仿军需店布局）：出售 **7 本炼气期 + 4 本筑基期**功法/术法（吐纳诀/火球术/青木长生功/御剑术·初窥…），明码标价 + 库存；购得后**自动装备入随身功法栏**（上限 5 种），栏满则**存入功法库**（档案页可手动装备）；灵石不足/已拥有/售罄均拦截
- **物品名称按稀有度着色**：普通（灰）/稀有（蓝）/珍贵（紫）/传说（橙）——储物袋、随身法宝、冒险者卡片徽章、结算面板、成员收获、炼器材料与产物全部按稀有度显示名称颜色
- **冒险者详情（ADVENTURER DOSSIER）**：参考原站档案布局——头部（名字 + Lv + 状态 + 小字 + **📜 探险日志按钮**（数字为该角色参与的日志数，点击弹出该角色全部探险日志：搜索 / 状态筛选 / 特殊事件与收藏筛选 / 分页，行内可收藏，点击进入日志详情后可返回列表））；**单页合并**：档案/战备/资产/传记四个区块纵向排布于一页，顶栏四个按钮仅作**跳转导航**（点击平滑滚动到对应区块，滚动时自动高亮当前区块，装卸/筛选后局部刷新且保持滚动位置）。区块内容：**档案**（气血/精力/四维/功法术法（5 格装备栏 + 功法库，可装卸）/特质）、**战备**（随身法宝与储物袋均使用与功法库相同的列表样式：名称 + 稀有度 + 描述 + 卸下/装备按钮；储物袋保留进度、稀有度筛选与排序）、**资产**（灵石/评分/赞 + 功法卷轴列表）、**传记**（探险履历统计 + 最近日志）；功法库与储物袋默认展示前 5 条，超出时右侧显示「展开全部 / 收起」按钮
- **匹配自选地图**：小队页招募板可选择地图（🎲 随机 或 7 座灵墟任选），选中后匹配按钮显示所选地图，开本进入所选灵墟（隐藏副本仍按 10% 概率触发）
- **无主角之分**（多人游戏设计）：步骤按成员轮转，谁被聚焦只取决于轮转顺序，不偏袒任何角色；队友是否出场按文本实际出现统计
- 每阶段做 **D20 骰子检定**：`属性修正 = (属性-10)/2` + 物品加成 + 特质加成 + **境界加成**（每 2 级 +1，封顶 +9，检定徽章上标注「境界+N」）
- **术法/功法优先**：战斗/首领步必定尝试释放技能（术法优先），探索/搜刮步按概率尝试；判定 **D20 + 术法3/功法2 + 灵根契合**（技能属性与施法者灵根**相同 → +2 增益**，相异或无属性不惩罚；**无境界/4 加成**，成功率与修为无关），效果直观体现在日志骰点徽章（「灵根+2」标注）与 AI 叙事中；**文本严格按技能描述演绎**（AI 与本地引擎均是），成功则灵光迸发、失败则施法受挫，日志与结算均有 📖 技能徽章
- **境界压制**：战斗/首领步判定时，**自身境界高于敌人每层 +1 优势（封顶 +4），低于敌人每层 -1 受制（封顶 -4）**（如练气八层对练气五层 +3；练气二层对筑基中期 -4）；敌人修为由【此间生灵】/【深处首领】标注，AI 叙事中自然体现威压与压制
- **性别代词**：创建角色可选性别（男/女），叙事（AI 与本地引擎）严格按角色性别使用「他/他的」或「她/她的」；NPC 随机性别；卡片/详情显示 ♂/♀
- **所有道具无属性值**，本地引擎按物品描述关键词映射效果（避瘴珠→探索+2、火球符→战斗+2、兽皮囊→搜刮+1 等），并写进剧情文本
- 性格、灵根、境界参与叙事；检定分级：自然20/≥18 大成功、≥12 成功、≥7 部分、≥2 失败、自然1 大失败

**AI 模式**（`index.html` 顶部 `AI_MODE` 常量）
- `remote`：POST `/api/ai/story` 调用你的后端 LLM（请求含队伍成员、带入物品、检定结果、步骤序号）
- **不再使用本地叙事文本**：AI 连接失败时**取消本次探险**——随机显示一段符合设定的取消理由（禁制重启、灵墟将崩、瘴雨蚀骨、凶兽挡道等 6 段），日志标注「失败」，退还精力，无战利品/灵石结算
- 探险文本生成完后，由 AI 为整篇日志写一段 **≤200 字总结**（`/api/ai/summary`），显示在日志详情「— 完 —」之前（✨ 探险总结）
- **AI 判定探险成败**（`/api/ai/outcome`）：结算时由 AI 通读最终剧情判定本次探险「成功 / 失败」——只要任务达成或全身而退即成功，单步大失败不算失败；判定理由展示在日志详情（✅/❌ 判定：…）；AI 不可用时回退旧规则（任一步大失败即失败）

**结算面板**
- 结算后**自动进入探险日志详情视图**（仿原站风格）：`探险日志 #id` 标题、队伍/灵墟/状态/时间元信息条、顶部摘要、**1~17 编号叙事段落**、每步 D20 检定徽章
- **日志持久化**：每次探险结束的日志自动存入 localStorage（`xiuxian_logs`，保留最近 100 条，收藏优先保留），刷新/关闭页面不丢失，随时回看
- **日志列表布局**（参考原站）：搜索框 + **按钮组筛选**（全部状态：已完成/失败/进行中/生成中 + 全部日志：✨特殊事件/⭐我的收藏）；行式条目：队伍名 · 副本名 · 摘要 · `日志 #ID` · 完整时间 · 状态徽章 · 人数 · ☆收藏（收藏持久化）；每页 10 条，页码分页（1 … N ‹ ›）；在线进入先渲染已有数据再后台同步（单请求去重），详情正文分块渲染，进行中日志增量追加
- **日志详情（对齐原站）**：工具条 A−/A/A+ 字号 + **四种阅读主题**（跟随主题/羊皮纸/夜间/护眼）+ **⛶ 全屏** + 名字高亮；顶部摘要 + 编号段落（**点击段落可发表评论**，随日志持久化）+ 探险总结 + 成员状态更新（新特质/新装备/属性增益）+ 点赞（每局限一次）
- 工具条：字号调整（A−/A+）、**名字高亮**开关（按成员着色的 `<mark>` 高亮）、返回列表
- **成员状态更新面板**：每名成员卡片显示 状态徽章（健康/受伤）、评分、+灵石、战损气血、新装备×数量 + 稀有度标签（普通/稀有/珍贵）
- **消耗品扣除**：丹药/符箓在剧情中经检定成功使用后，结算时从储物袋（或随身法宝）**自动扣除 1 个**；日志详情与结算弹窗均显示「🧪 剧情中消耗的道具（已扣除）」，工具类（避瘴珠等）不消耗
- **剧情驱动的战利品（一切以文本为准）**：**舍弃副本 loot 表**——结算时由 AI 从整篇探险文本**语义提取**战利品（`/api/ai/extract_loot`，能区分"获得"与"提及"，杜绝"兽皮囊"被误认成"兽皮"这类问题），AI 自由创造符合副本设定的道具名并为每件编写描述；提取失败时回退【获得：】标记；本地引擎回退时保留随机保底掉落
- **灵石按剧情分配**：剧情文本提到灵石（如"得了五十块灵石"）才分配，按文本数量入账（支持阿拉伯数字与汉字数字）；剧情未获得灵石则分文不给
- **重伤体系**：结算时气血低于 10% 判定重伤，按剧情受伤表现添加受伤特质（战斗大失败→重伤未愈、中毒→中了尸毒、受惊→惊吓过度…），特质带 **3 小时现实倒计时**徽章（⏳ 每秒刷新），到期自动消失并提示恢复
- **给队友点赞**区
- **进行中的副本**在列表页只显示一条简洁日志卡（副本名 + 队伍 + "进行中"徽章，**不显示步骤**）；点击进入详情后**实时显示冒险进程**（编号步骤随副本推进自动刷新，**不显示阶段条与当前阶段**，隐藏游戏结构让玩家更有沉浸感），结算后自动切入结算日志详情
- 玩家实际收益：获得经验、搜刮道具（自动入储物袋）、新特质、修为突破；历史日志列表点击任意一条可进入详情重看
- **突破系统（筑基门槛）**：练气十层满修为（1000 经验）后经验封顶、**不再自动升入筑基**（修为条显示「圆满」）；满修为角色进入副本有 **10% 概率触发突破事件**——AI 在副本中安排**突破试炼**（天劫淬体/心魔问心/道基重铸等），试炼步判定成功（good/crit）则结算时**突破至筑基前期**（等级 11、经验清零、气血上限提升，流水记录突破），失败则维持练气十层待下次再试

## 数据说明

所有显示数据都在 `data.js` 顶部的 `window.TAVERN_DATA` 对象中，包含：

- `user` — 用户信息（昵称、余额）
- `tavern` — 酒馆标题、副标题、公告、测试提示
- `adventurers` — 24 名冒险者（真实数据：等级、四维、金币、职业、性格、特质、装备、状态）
- `seats` — 18 个酒馆座位（冒险者 + 酒水 + 描述文本）
- `chat` — 30 条酒馆闲聊消息
- `activity` — 赌王大赛完整数据（规则、阶段、排名）
- `buildings` — 50 栋建筑（分区、状态、描述）
- `drinks` — 27 种酒水菜单（名称、价格、描述）
- `matchmaking` — 21 张副本地图 + 匹配统计
- `logs` — 探险日志
- `npcs` — 各页面顶部的事件 NPC

## 如何改成你自己的游戏

1. **改数据**：编辑 `data.js`，替换冒险者、酒水、建筑、日志等内容。
2. **改界面**：`style.css` 顶部的 `:root` 变量控制全套配色（背景/边框/主色/黄铜主题色等）；顶栏 🎨 按钮可在**白色仙侠风（默认）与暗色**之间切换（`[data-theme="light"]` 覆盖变量，选择存入 localStorage `xiuxian_theme`）。
3. **改模块**：`index.html` 中每个 `renderXxx()` 函数对应一个标签页模块，可增删改。
4. **接后端**：把 `data.js` 里的静态数据替换为 `fetch('/api/...')` 请求即可对接真实后端。

## 与原站的差异说明

- 原站为 Vue 3 + Naive UI 单页应用；本复刻为纯 HTML/CSS/JS，无任何框架依赖，便于二次开发。
