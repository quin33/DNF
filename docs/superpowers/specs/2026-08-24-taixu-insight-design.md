# 太虚幻境 AI 参悟设计

## 目标

在建筑模块新增「太虚幻境」。玩家选择功法或术法，输入不超过 100 字的期望目标；服务端结合角色当前境界、灵根、特质、已装备能力和功法库，调用 AI 生成符合世界观且强度合理的新能力，并原子写入角色数据。

功法与术法继续使用现有阶位体系作为稀有度：黄阶、玄阶、地阶、天阶。不新增普通、稀有、珍贵、传说字段。

## 用户流程

1. 玩家在建筑页点击「太虚幻境」。
2. 弹窗展示角色境界、灵根、特质、功法栏和功法库概况。
3. 玩家通过分段控件选择「功法」或「术法」。
4. 玩家输入 1 至 100 字的期望目标并提交。
5. 提交期间按钮禁用，防止重复参悟。
6. 服务端读取角色最新状态、调用 AI、校验结果并保存。
7. 成功后弹窗展示能力名称、类型、阶位、属性、描述及保存位置。
8. 功法栏未满时自动装备；功法栏已满时存入功法库。
9. 最近动态新增一条太虚幻境参悟记录。

## 建筑与前端

在建筑数据中增加：

```js
{
  code: 'taixu_realm',
  name: '太虚幻境',
  category: '修炼',
  status: 'built'
}
```

建筑页将其纳入现有修炼设施列表。卡片点击后打开独立参悟弹窗。

弹窗包含：

- 功法/术法分段选择。
- `maxlength="100"` 的目标文本输入。
- 实时字数显示。
- 角色上下文摘要。
- 参悟按钮、生成中状态、错误状态和结果状态。
- 费用与冷却说明；当前均显示免费、无冷却。

前端只提交玩家选择、目标文本和角色版本号。境界、灵根、特质及已有能力由服务端读取，避免被客户端篡改。

## 服务端接口

新增权威接口：

```text
POST /api/character/:id/taixu-insight
```

请求：

```json
{
  "type": "功法",
  "goal": "希望参悟一门适合火灵根、能够持续护体的功法",
  "updated_at": 123
}
```

响应：

```json
{
  "ok": true,
  "skill": {
    "name": "赤霞护元诀",
    "type": "功法",
    "tier": "玄阶",
    "elem": "火灵根",
    "desc": "能力效果、适用场景与限制"
  },
  "storage": "equipped",
  "character": {},
  "updated_at": 124,
  "cost": {
    "gold": 0,
    "stamina": 0,
    "cooldownMs": 0
  }
}
```

`storage` 为 `equipped` 或 `pool`。

## AI 输入与输出

AI 上下文包括：

- 玩家选择的功法或术法类型。
- 期望目标。
- 角色姓名、境界、灵根和特质。
- 已装备功法术法及功法库中的名称、类型、阶位、属性和描述。
- 当前世界观、修炼体系和能力强度约束。

AI 严格输出单个 JSON 对象：

```json
{
  "name": "能力名",
  "type": "功法",
  "tier": "玄阶",
  "elem": "火灵根",
  "desc": "能力效果、适用场景与限制"
}
```

生成规则：

- `type` 必须与玩家选择一致。
- `tier` 只能是黄阶、玄阶、地阶、天阶。
- 能力必须符合修仙世界观和角色当前境界。
- 过强或无法实现的目标必须降格为当前角色可掌握的版本，不得直接赋予越级碾压能力。
- 结合灵根与特质，但不强制所有能力都与灵根同属性。
- 避免与已有能力名称或定位重复。
- 描述应明确效果、适用场景和限制，不承诺当前游戏系统无法表现的精确数值效果。

## 校验与持久化

服务端校验：

- 用户已登录且角色属于当前用户。
- `updated_at` 与数据库版本一致。
- `type` 为功法或术法。
- `goal` 去除首尾空白后长度为 1 至 100 字。
- AI 返回字段完整，类型与阶位属于白名单。
- 名称、描述长度合法且不含乱码替换字符。
- 名称不与功法栏或功法库重复。

AI 返回格式异常或重名时最多自动重试三次。三次均失败则返回错误，不改变角色数据。

校验通过后，服务端调用现有技能写入规则：功法栏未达到上限时写入 `skills`，否则写入 `skillPool`。角色保存采用版本条件更新，能力写入与费用扣除必须处于同一次权威结算中。

## 费用与冷却接口

服务端定义集中配置：

```js
const TAIXU_INSIGHT_COST = {
  gold: 0,
  stamina: 0,
  cooldownMs: 0,
};
```

当前不扣除资源、不限制冷却。接口仍执行统一的资源和冷却校验函数，后续只需修改配置即可启用，不改变前端请求协议。

角色数据可预留最近参悟时间字段；当 `cooldownMs` 为零时不阻止请求。

## 最近动态

成功参悟后新增单条动态，内容包括：

- 标题：能力名称。
- 来源：`太虚幻境 · 参悟功法` 或 `太虚幻境 · 参悟术法`。
- 阶位标签：黄阶、玄阶、地阶或天阶。
- 描述：AI 生成的能力描述。
- 保存位置：功法栏或功法库。

失败请求不写入动态。

## 错误处理

- AI 服务不可用：提示稍后重试，不写入角色。
- AI JSON 异常或字段非法：服务端自动重试，耗尽后返回明确错误。
- 重名：自动重试；耗尽后提示未能参悟出新能力。
- 角色版本冲突：返回 409，前端刷新角色后提示重新提交。
- 输入为空或超过 100 字：前后端同时阻止。
- 重复点击：前端禁用提交按钮，服务端版本校验防止重复落库。

## 测试

自动化测试覆盖：

- 建筑数据、建筑卡片和弹窗入口存在。
- 类型选择与 100 字输入限制。
- 请求只提交类型、目标和角色版本。
- AI 上下文包含境界、灵根、特质、功法栏和功法库。
- AI 返回类型、阶位、名称和描述白名单校验。
- 过强目标的提示词约束。
- AI 异常与重名重试三次，失败时角色不变。
- 功法栏有空位时自动装备。
- 功法栏已满时写入功法库。
- 版本冲突不覆盖新数据。
- 当前免费、无冷却，并保留费用与冷却配置。
- 成功参悟写入最近动态，失败不写入。

## 验收标准

- 玩家可以在太虚幻境选择功法或术法并提交不超过 100 字的目标。
- 生成能力与角色状态、已有能力和世界观一致。
- 阶位由 AI 根据效果强度决定，且仅使用黄、玄、地、天阶。
- 成功结果可靠持久化，刷新后仍存在。
- 不产生重复能力，不因失败请求扣除资源或污染角色数据。
- 后续启用灵石、精力和冷却时无需改变接口。
