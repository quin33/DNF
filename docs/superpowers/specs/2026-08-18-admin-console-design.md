# 后台管理系统设计

## 目标

提供独立的管理后台，用于检索全部玩家并编辑其角色数据。后台不开放账号密码、玩家会话、探险日志或删除功能。

## 认证与授权

- 后台入口为 `GET /admin`，页面独立于游戏前台。
- 管理员密码只从 `ADMIN_PASSWORD` 环境变量读取，不保存到数据库、配置文件或浏览器存储。
- `POST /api/admin/login` 校验密码并创建独立管理员会话。会话令牌使用安全随机值，保存到 SQLite，默认有效期为两小时。
- 所有 `/api/admin/*` 接口要求有效管理员会话。未配置管理员密码时，后台入口和接口均拒绝服务。
- 普通玩家的 Bearer 会话不能调用管理员接口。

## 数据模型

新增两张 SQLite 表：

- `admin_sessions`：令牌、创建时间、过期时间。
- `admin_audit_logs`：操作时间、目标用户 ID、目标角色 ID、变更前摘要、变更后摘要。

角色仍保存在既有 `characters.data` JSON 字段中。后台只允许修改白名单字段：

- `name`、`character_class`、`level`、`hp`、`max_hp`、`stamina`、`max_stamina`
- `strength`、`agility`、`intelligence`、`luck`、`gold`、`exp`
- `traits`、`equipment`、`bag`、`skills`、`skillPool`

账号密码、盐值、玩家会话、日志及任何未列出的字段不可由后台更新。

## 接口

- `POST /api/admin/login`：提交管理员密码，返回管理员令牌。
- `POST /api/admin/logout`：销毁当前管理员会话。
- `GET /api/admin/players?q=`：按用户名或角色名搜索玩家，返回玩家和角色摘要。
- `GET /api/admin/characters/:id`：返回指定角色完整数据及所属玩家。
- `PUT /api/admin/characters/:id`：提交白名单角色字段和 `updated_at` 版本号；服务端校验后保存并写入审计日志。
- `GET /api/admin/audit?characterId=`：返回指定角色的最近审计记录。

所有写入接口使用参数化 SQL，返回通用鉴权错误，不暴露管理员密码或环境配置状态。

## 后台界面

- 左侧为搜索与玩家/角色列表，右侧为所选角色的编辑表单和最近审计记录。
- 编辑区域按基础信息、属性资源、特质、随身法宝与储物袋、功法分组。
- 复杂数组以 JSON 文本区编辑，保存前由浏览器和服务端同时校验为数组。
- 保存按钮显示本次变更摘要；成功后更新角色版本和审计记录。
- 首版不包含创建、删除角色或直接 SQL 编辑功能。

## 校验与并发

- 数值字段必须是有限数字，资源值不得为负数，当前值不得大于对应上限。
- 文本长度和数组项数量受服务端上限约束；随身法宝、储物袋、功法与特质必须具有预期的基础结构。
- 写入以 `updated_at` 乐观锁保护。版本不一致时返回冲突，后台提示重新加载。
- 管理员会话过期后回到登录页。

## 测试

- 未认证和普通玩家令牌均无法访问管理员接口。
- 正确与错误的管理员密码分别创建或拒绝创建后台会话。
- 玩家搜索、角色详情读取和白名单字段保存可用。
- 非白名单字段、非法 JSON、非法数值和版本冲突均被拒绝。
- 每次成功保存新增一条包含前后摘要的审计记录。
- 既有玩家角色 API 与页面回归测试继续通过。
